This document states what is formally checked in this repository, how it is
checked, and what is not. It was rewritten on 2026-10-30 from the files in the
tree; the earlier version was a placeholder with no content.

== Status

The naming and identity claims are formally checked in Agda and the check runs
in CI on every pull request that touches the proofs. Nothing else in the Julia
package, the Zig FFI, or the (absent) Idris2 ABI is formally verified.

== What is proved

Module `proofs/agda/PackageNaming.agda` proves, about the map from a package
name to its repository name (`package ++ ".jl"`):

[cols="1,2"]
|===
| `repoNameOf-injective` | Two different package names never produce the same repository name.
| `round-trip` | The package name can be recovered from the repository name.
| `repoNameOf-not-identity` | The repository name is never the same string as the package name. This is why the two names can drift apart at all.
| prefix uniqueness | `packageNameOf` is well-defined: the `.jl` suffix is stripped exactly once, by the `RepoForm.prefix` field, using `append-cancel-right`.
|===

The live identity is supplied as generated data. `CanonicalIdentity.agda`
(generated by `scripts/gen-identity-agda.sh`) holds the package name read from
`Project.toml` and the repository name from `GITHUB_REPOSITORY`. The equality
between them is discharged by `refl`, so Agda's own evaluator decides it.
`IdentifierCharset.agda` and `RetiredNames.agda` are generated the same way.

== How it is checked

* Every module is typechecked with
  `agda --no-libraries --safe --without-K --double-check --ignore-interfaces -W error`,
  using Agda 2.6.4.3 in a digest-pinned `debian:13-slim` container. The version is
  asserted before any proof runs. The job fails if Agda is absent; it does not skip.
* `scripts/check-agda-trusted-base.sh` scans the proof and negative-control
  modules for postulates, holes, disabled checks (`TERMINATING`,
  `NO_POSITIVITY_CHECK`, `--type-in-type`, `--rewriting`, and similar). The budget
  is 0. Last result: 0 violations across 12 modules.
* Negative controls in `tests/reject/` (seven files) must each fail with Agda's
  type-error status 42 and with the expected mismatch diagnostic, checked by
  `tests/check-rejections.sh`. The fixture list must equal the files on disk.
* The identity checker `tests/check-identity.sh` and its fixture suite
  `tests/check-identity-fixtures.sh` cover the non-Agda side: names in
  `Project.toml`, the module declaration, `using` in tests, README consistency,
  self-referencing URLs, and the retired-name register. Its fixture suite runs 24
  cases: 22 broken trees that must be rejected and 2 consistent trees that must be
  accepted.

== Not proved

* The Julia generator (`src/generator.jl`). Its tests (`test/`) run on Julia 1.10
  and 1.11 in CI, but they are not proofs.
* The Zig FFI in `ffi/zig/`. It does not compile: `main.zig` declares its `Handle`
  as an `opaque` type with fields, which Zig rejects, and `build.zig` uses build
  APIs that do not exist in Zig 0.13, 0.14 or 0.17 (tested locally). This is a
  baseline defect, not a regression from the rename. Nothing in `ffi/zig/` is
  verified.
* The Idris2 ABI. The Idris2 sources are not in the tree, so there is nothing to
  verify. `ABI-FFI-README.adoc` describes it as planned.
* The `ci_profile` option. It is stored on the spec and does not change generated
  output. The `ffi_enabled` option only creates empty `ffi/zig` and ABI
  directories; it writes no Zig or Idris2 files.
* Reuse auditing. It is planned for v0.3.0 and not implemented.
