== JuliaPackageSpitter.jl ABI/FFI Documentation

=== Status

What exists in this repository:

* A C-compatible FFI library written in Zig, in `ffi/zig/`. Its exports are
  declared in the hand-written header `ffi/zig/include/juliapackagespitter.h`.
* Lifecycle, version, string and last-error functions work. `process`,
  `process_array` and `register_callback` are placeholders: they validate their
  arguments and do nothing else.
* Build and tests pass on Zig 0.14.1: `zig build test` runs 17 tests.

What is planned but NOT in this repository:

* An Idris2 ABI definition and generated C headers. The intended design is an
  Idris2 module set that generates the C header, but no Idris2 sources, no
  generated header and no proofs about the ABI exist here. Nothing in this file
  describes a verified ABI.
* Language bindings. None exist.

=== Layout

....
ffi/zig/
├── build.zig                         # build and test steps (Zig 0.14.x)
├── include/juliapackagespitter.h     # C declarations; hand-written
├── src/main.zig                      # the implementation and its unit tests
└── test/integration_test.zig         # tests that call the library through its C ABI
....

=== Building and testing

[source,bash]
----
cd ffi/zig
zig build                 # builds the shared and static libraries and installs the header
zig build test            # unit tests and integration tests (17)
----

The build targets Zig 0.14.x. The build API changed between Zig releases, so
`build.zig` does not compile on other versions.

=== Keeping the header in sync

`include/juliapackagespitter.h` is written by hand. When an export in
`src/main.zig` changes its signature, update the header in the same change.
Nothing checks this automatically yet.

=== Memory and ownership

* `juliapackagespitter_get_string` returns a string the caller must release with
  `juliapackagespitter_free_string`.
* `juliapackagespitter_last_error` and `juliapackagespitter_version` return static
  strings. The caller must not free them.
* `juliapackagespitter_free(NULL)` is a no-op. Freeing the same handle twice is
  undefined behaviour and is not tested.
* The library uses libc's allocator, so it links against libc.
